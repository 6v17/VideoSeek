# VideoSeek 近期讨论 · 优化汇总

维护者存档（2026-10-29）。这是决策备忘，不是已实现规格。落地时以代码为准，做完再回写状态。

未拆：只给作者看的 PR 清单、用户设置项清单。

---

## 1. 总原则

```text
先吃透 CLIP（工程 + 用法 + 展示）
再考虑本地 VL Embedding 2B
云 API 向量暂缓（命门在厂商、换维要重建）
```

准确率问题要拆开：

| 现象 | 主因 | 优先手段 |
|------|------|----------|
| 有点准、夹杂噪声 | 排序/展示/弱精排 | 阈值、邻域精排 |
| 不全、不密 | 索引里没有 + top 截断 | 抽帧密度（需重同步）、单集多召回 |
| 抽象/情绪词差 | CLIP 上限 | 改写、以后 2B |
| 多集 OP/ED 重复 | 跨集相同画面 | 组合展示，硬去重慎用 |

## 2. CLIP 阶段：提准（不换模型）

### P0 · 优先做

| 项 | 内容 | 是否重建库 |
|----|------|------------|
| **文搜邻域精排** | 复用图搜逻辑。文搜与图搜共用 `frame_neighbor_rerank_enabled`（默认开）：对 top-N 在邻域窗口内用同一 query 向量重打分，贴更准的帧。深入搜索仍不走这条 | 否 |
| **分数阈值** | 排序后砍低分，默认少而精，滚动再加载 | 否 |
| **文搜增强开关** | 配置里有 `text_search_enhance_enabled`，默认 false → 可开；规则/同义/多路，能力有限但零成本 | 否 |
| **范围** | 单集/少库再搜（产品已有，不是新功能） | 否 |

### P1 · 次优先

| 项 | 内容 | 是否重建库 |
|----|------|------------|
| **scoped 加大 fetch** | 已选范围时多取候选再截断，减轻「相关帧在 top 外」 | 否 |
| **查询改写** | 可选 **API**（能进能退）或小词表；虚词→画面短句；失败则原句；结果可编辑 | 否 |
| **写法引导** | 提示写颜色/服装/景别/动作，少写剧情情绪 | 否 |

### P2 · 按需

| 项 | 内容 | 是否重建库 |
|----|------|------------|
| **提高抽帧密度** | 1fps 是务实默认，不低；快切短特写仍会漏。加密 = **再同步/重建**，不要与「搜时调参」混淆 | **是** |
| **Large 档 A/B** | 同系列 Chinese-CLIP / SigLIP2 Large | 换模型要重嵌 |
| **同镜/相似组合展示** | 见下节 | 否 |

## 3. 结果展示：重复与 OP/ED

### 原则

```text
搜索浏览：组合展示 > 硬去重删除
导出/素材篮：可再提供「每镜一条」
```

### 固定时段 skip

- 已有时间窗跳过思路，适合「大概片头/片尾 N 分钟」
- **不适合** OP/ED 每集时间不固定

### 展示

列表仍是现在的表格和网格。多条收成一条代表（组内最高分）。角标写在视频名或卡片时间上：同一集是「邻近 · N」，跨集是「跨集 · N」。列表和网格点角标都只显示这一组，状态条左侧用「返回结果」回到原来的位置。单独一条不显示角标。加入素材篮时，收起只加代表条。文搜片段的缩略图和预览落在组内得分最高的那一帧。

开关在高级参数里的「聚组」：关闭 / 宽松 / 标准 / 严格。默认标准。灵敏度只收紧跨集合并。

### 推荐后处理管道

```text
1. 召回 top-K（可略多）
2. 按 score 排序
3. 分数阈值
4. 聚组（不要「每 N 条切一组」）
5. 每组一个代表（组内最高分），点进去看其余命中
```

### 聚组怎么做

| 选择 | 结论 |
|------|------|
| **候选向量比** vs 再抽帧比图 | **用向量**，成本低、与 CLIP 空间一致 |
| 时间复杂度 | **O(n²·d)**，不是 n!；n=50～200 可忽略 |
| 分批 | **按 video_id 分桶**，桶内再比；跨集第二遍更严阈值 |
| 同 OP 跨集 | 相似度通常很高，但同番正片也可能高 → **阈值自管、默认偏严** |

```text
同视频 + 时间近 → 可松
跨视频合并 → 更严
开关 + 灵敏度给用户
```

## 4. 查询侧：抽象词（笑容等）

```text
少搜「笑容」→ 露齿、嘴角上扬、近景脸等
有参考帧 → 图搜往往更稳
同义表：高频可做，非通用完善体系
词典释义 ≠ 直接当 query；可抠可见词
轻量本地 LLM（如 Qwen2.5-0.5B）可改写，但更推荐先 API 改写
```

中文视觉：CLIP 系已齐（OpenAI / Chinese-CLIP / SigLIP2 的 base+大档）；新一代 2B 多模态是下一步，不是「漏接了一个小 CLIP」。

## 5. 模型路线（暂缓顺序）

```text
① 完善 CLIP 工程（上表）
② 可选本地 Qwen3-VL-Embedding-2B（GPU、独立 profile、重嵌）
③ 可选 Rerank 2B（只打 top-K，不与 ② 绑死第一版）
④ 云 API 向量：设置里可选 DashScope `qwen3-vl-embedding`（默认关，独立档案，维度钉死；换维=另一套空库）
```

### 2B 备注

- 抽象句预期明显强于经典 CLIP；接入是 **新 provider**，不是再丢一个 zip
- **4060 + 32G**：搜索一般可接受；建库比 CLIP 慢数倍～一个数量级
- 参考：你机 CLIP **约 1400 帧 ≤20s**；同帧数 2B 多半是 **分钟级**，需实测倍数
- 公开 R@1 对比可参考，勿当番剧场景保证

### API 向量

- 形态：文本/帧 → API 出向量 → **本地 Lance 检索**（建库也须同一模型）
- 已接一版备选：设置「云嵌入备选」。模型 `qwen3-vl-embedding`，默认维度 2048，北京 DashScope。开启前要确认：抽出的帧和查询会上传到配置的云端。向量在 `model_assets/qwen3-vl-embedding-cloud/qwen3-vl-embedding-2048/`，和 Chinese-CLIP 分开。`cloud_vl_embedding.base_url` 可改。
- 风险：厂商换模/换维 → 本地库要重建；命门在厂商。帧和查询会离开本机。

## 6. 明确不优先

```text
为「不准」先换 Lance
默认全员上 2B / 默认云嵌入
用 n! 或重抽帧做聚组
指望 1fps→2fps 解决所有「不准」（且要重建）
硬去重当默认搜结果策略
```

---

## 7. 建议落地顺序

```text
1. 文搜邻域精排 + 确认增强可开
2. 分数阈值 + 列表少而精
3. 候选向量聚组展示（分桶、点进去看）
4. 可选 query 改写（API/词表）
5. 重要库再考虑加密抽帧重同步
6. 吃透后可选 VL Embedding 2B
```

---

## 8. 一句话版

```text
准：精排 + 阈值 + 写法/改写 + 选对模型
全：索引密度（要重建）+ 召回条数
净：向量聚组展示，不去死扣删
后：本地 2B → 再 API；CLIP 先吃透
```
