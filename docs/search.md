# 搜索条数

桌面搜索和找图怎么决定「这一次取多少、滚下去再取多少」。改窗口或上限时，先改下面表里的函数，再改这篇。

架构总览在 [`architecture.md`](architecture.md)。Agent 字段在 [`for-agents.md`](for-agents.md)，那篇不覆盖这里的翻页规则。

## 桌面结果窗口

不写死 `top_k` 的桌面搜索从 **300** 起。视口离这一窗的末尾还差 **100** 行时，整次重新搜，窗口翻倍：

```text
300 → 600 → 1200 → 2400 → 4800 → 9600 → 10000
```

10000 是安全顶。到了就停，状态可以带「已到 1 万条上限」。

这一页比窗口短（片段搜索会把很多帧收成少量段），用户滚到**最后一行**仍会翻倍。只有翻倍之后没有新行、而且返回条数少于这次请求，才算到头。空结果也到头。

调用方写了明确的 `top_k`（Agent、预设）不翻倍，只按那个数，并且不超过 10000。

每次翻倍都是整次重搜，不是从上次的游标接着取。

| 常量 | 值 | 位置 |
|------|----|------|
| `SEARCH_WINDOW_INITIAL` | 300 | `src/storage/config_store.py` |
| `SEARCH_WINDOW_LEAD` | 100 | 同上 |
| `SEARCH_TOP_K_MAX` | 10000 | 同上 |
| 视频各 tab 何时翻 | | `ui/controllers/search_controller.py` |
| 找图何时翻 | | `ui/controllers/image_gallery_controller.py` |

`next_result_window` 是唯一的翻页判断。视频搜索和找图都用它。

## 各 tab 能取回多少

| 入口 | 结果窗口 | 和窗口一起走 |
|------|----------|----------------|
| 图搜、文搜、组合搜 | 300 起，翻倍到 1 万 | 是。见下一节的扩召回 |
| 字幕 | 同上 | 是。SQL 的 limit 就是这次窗口 |
| 标签 | 同上 | 是 |
| 找图 | 同上 | 是。精确余弦，没有视频那种「多取再补」 |

找图以前固定 60 条，不翻页。现在和上面同一套窗口。

## 扩召回常数

`src/services/search_fetch_policy.py` 里的 200 / 400 / 500 **不是结果条数的天花板**。它们只限制「比窗口多取的那一截」，公式是：

```text
取回条数 = max(窗口, min(常数, 扩出来的数))
```

窗口一旦大于常数，取回的就是窗口本身。所以 600、1200、10000 都会按那个窗口重新取，翻倍不是空跑。

| 常数 | 谁在用 | 窗口还小的时候 |
|------|--------|----------------|
| `_SOURCE_FILTER_FETCH_CAP = 500` | 图搜快搜、文搜、组合搜 | 窗口 300 时实际取 500，用来补被缺文件丢掉的行。界面仍先显示 300 |
| `_PRECISE_FETCH_CAP = 200` | 深入（像素重排那路） | 桌面第一页已是 300，所以深入第一页取的是 300 |
| `_GLOBAL_STAGE1_FETCH_CAP = 400` | 深入、而且没选素材范围时的第一阶段 | 窗口更大时跟着窗口 |
| `resolve_chunk_precise_frame_fetch_k` 里的 200 | 片段模式先按帧取、再收成段 | 同一公式 |
| `resolve_fetch_top_k` 里的 200 | 选了素材范围时多取再丢掉范围外的 | 结果不会少于窗口 |
| `_EDGE_FETCH_CAP = 500` | 打开了跳过时段时，再把池子加大 | 不会把已经更大的 fetch 削小 |

窗口超过这些常数之后，多取的缓冲没有了。缺文件、片头片尾滤掉的行，不一定还能补满当前这一窗，但下一档窗口仍会带回更靠后的命中。

## 图搜的四种样子

搜索页图搜模式（`image_search_mode`）：

| 值 | 行为 |
|----|------|
| `frame` | 按帧。快搜 |
| `video_discovery` | 每条视频只留最好的一处。仍是快搜 |
| `precise` | 深入。先召回，再对最靠前的几条做像素重排 |
| `chunk` | 收成片段 |

纯文搜不走深入。组合搜带了参考图时可以深入。

## 字幕和标签

- 精确：SQLite 子串。
- 模糊：先比完整子字段，再比散落命中率。模糊 SQL 候选上限是 `max(500, min(8000, 请求 × 100))`，这是扫描行数，不是界面上的结果条数。
- 字幕范围、标签范围和画面库范围是分开的。选了范围时，结果 limit 仍是这次窗口；200 只裁掉多取的候选。

## 找图

- 索引在当前模型 profile 的 `image_gallery/`，和视频帧表分开。
- 精确余弦排序，再用**组合搜那条最低分**丢掉太低的。
- 窗口与上表相同。省略 `top_k` 时用 `resolve_image_gallery_top_k`（第一页 300，显式数字不超过 1 万）。
- 缩略图只解当前屏和往后一屏，不把整窗图片一次解码。
- 不按视频素材范围过滤。

## 其它会改结果的开关

- **最低分**：按类型存在配置里（`image` / `text` / `compose` / `dialogue` / `image_chunk`）。0 表示不过滤。找图用组合搜那条。
- **素材范围**：全部，或选中的库 / 视频。选中后先多取，再丢掉范围外的。
- **跳过时段**：同一组绝对时间套到每条视频上。剩余不足 30 秒的视频整段保留。
- **文搜增强**：多路查询再做 RRF，最后仍截到这次窗口。
