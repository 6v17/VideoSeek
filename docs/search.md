# 搜索条数和排序

桌面、本机 Agent API、服务机 / 用户机怎么决定「这一次取多少」，以及结果怎么重排、聚组。改窗口、上限或这些开关时，先改下面表里的函数，再改这篇。

架构总览在 [`architecture.md`](architecture.md)。Agent 的字段和错误码在 [`for-agents.md`](for-agents.md)；翻页和条数以这篇为准。

## 桌面结果窗口

不写死 `top_k` 的桌面搜索从 **300** 起。视口离这一窗的末尾还差 **100** 行时，整次重新搜，窗口翻倍：

```text
300 → 600 → 1200 → 2400 → 4800 → 9600 → 10000
```

10000 是安全顶。到了就停，状态可以带「已到 1 万条上限」。

这一页比窗口短（片段搜索会把很多帧收成少量段），用户滚到**最后一行**仍会翻倍。只有翻倍之后没有新行、而且返回条数少于这次请求，才算到头。空结果也到头。

翻倍只发生在桌面界面。Agent 和预设如果写了 `top_k`，就按那个数搜一次，不翻倍，并且不超过 10000。

每次翻倍都是整次重搜，不是从上次的游标接着取。

| 常量 | 值 | 位置 |
|------|----|------|
| `SEARCH_WINDOW_INITIAL` | 300 | `src/storage/config_store.py` |
| `SEARCH_WINDOW_LEAD` | 100 | 同上 |
| `SEARCH_TOP_K_MAX` | 10000 | 同上 |
| 视频各 tab 何时翻 | | `ui/controllers/search_controller.py` |
| 找图何时翻 | | `ui/controllers/image_gallery_controller.py` |

`next_result_window` 是唯一的翻页判断。视频搜索和找图都用它。

## 各 tab 能取回多少

| 入口 | 结果窗口 | 和窗口一起走 |
|------|----------|----------------|
| 图搜、文搜、组合搜 | 300 起，翻倍到 1 万 | 是。见下一节的扩召回 |
| 字幕 | 同上 | 是。SQL 的 limit 就是这次窗口 |
| 标签 | 同上 | 是 |
| 找图 | 同上 | 是。精确余弦，没有视频那种「多取再补」 |

找图以前固定 60 条，不翻页。现在和上面同一套窗口。

## 扩召回常数

`src/services/search_fetch_policy.py` 里的 200 / 400 / 500 **不是结果条数的天花板**。它们只限制「比窗口多取的那一截」，公式是：

```text
取回条数 = max(窗口, min(常数, 扩出来的数))
```

窗口一旦大于常数，取回的就是窗口本身。所以 600、1200、10000 都会按那个窗口重新取，翻倍不是空跑。

| 常数 | 谁在用 | 窗口还小的时候 |
|------|--------|----------------|
| `_SOURCE_FILTER_FETCH_CAP = 500` | 图搜快搜、文搜、组合搜 | 窗口 300 时实际取 500，用来补被缺文件丢掉的行。界面仍先显示 300 |
| `_PRECISE_FETCH_CAP = 200` | 深入（像素重排那路） | 桌面第一页已是 300，所以深入第一页取的是 300 |
| `_GLOBAL_STAGE1_FETCH_CAP = 400` | 深入、而且没选素材范围时的第一阶段 | 窗口更大时跟着窗口 |
| `resolve_chunk_precise_frame_fetch_k` 里的 200 | 片段模式先按帧取、再收成段 | 同一公式 |
| `resolve_fetch_top_k` 里的 200 | 选了素材范围时多取再丢掉范围外的 | 结果不会少于窗口 |
| `_EDGE_FETCH_CAP = 500` | 打开了跳过时段时，再把池子加大 | 不会把已经更大的 fetch 削小 |

窗口超过这些常数之后，多取的缓冲没有了。缺文件、片头片尾滤掉的行，不一定还能补满当前这一窗，但下一档窗口仍会带回更靠后的命中。

## 图搜的四种样子

搜索页图搜模式（`image_search_mode`）：

| 值 | 行为 |
|----|------|
| `frame` | 按帧。快搜 |
| `video_discovery` | 每条视频只留最好的一处。仍是快搜 |
| `precise` | 深入。先召回，再对最靠前的几条做像素重排 |
| `chunk` | 收成片段 |

纯文搜不走深入。组合搜带了参考图时可以深入。

## 字幕和标签

- 精确：SQLite 子串。
- 模糊：先比完整子字段，再比散落命中率。模糊 SQL 候选上限是 `max(500, min(8000, 请求 × 100))`，这是扫描行数，不是界面上的结果条数。
- 字幕范围、标签范围和画面库范围是分开的。选了范围时，结果 limit 仍是这次窗口；200 只裁掉多取的候选。

## 找图

- 索引在当前模型 profile 的 `image_gallery/`，和视频帧表分开。
- 精确余弦排序，再用**组合搜那条最低分**丢掉太低的。
- 窗口与上表相同。省略 `top_k` 时用 `resolve_image_gallery_top_k`（第一页 300，显式数字不超过 1 万）。
- 缩略图只解当前屏和往后一屏，不把整窗图片一次解码。
- 不按视频素材范围过滤。

## 本机 Agent API

本机 `127.0.0.1` 的 `/api/v1/search` 走同一套 `search_service` 和上面的扩召回常数。没有桌面那种滚到底再翻倍。

- 省略 `top_k`：300（`get_search_top_k`）。
- 写了 `top_k`：原样使用，夹在 1 到 10000。一次响应就是这些条，没有页码或 offset。
- 请求里的 `scope` 覆盖桌面当前选的素材范围。没写 scope 时，跟桌面当前范围。
- 跳过时段用这台机器保存的规则，请求体改不了。字幕和标签不走这道过滤。
- 找图不在 Agent API 里。

批量搜索里，单条没写 `top_k` 时用这一批的默认值，再按上面夹紧。

## 服务机和用户机

用户机的视频搜索（图搜、文搜、组合、字幕、标签）仍由**用户机界面**翻倍。每一档窗口都是一次新请求，把当前的 `top_k` 交给服务机。服务机不自己翻倍，只按这个数跑同一套 `search_service`，所以上面的 200 / 400 / 500 扩召回发生在服务机上。

- 用户机可以文字搜、图片搜服务机已经索引的库。图片由服务机按它当前的模型编码。
- 添加库、收录、刷新、同步只在本机或服务机上做。用户机不做。
- 跳过时段是服务机的规则，用户机看得到、改不了，也不能在单次请求里覆盖。
- 找图不走服务机。用户机上的找图仍搜这台电脑自己的图片文件夹，窗口规则和上面的「找图」一节相同。

服务机对外的检索就是它上面的 Agent API（局域网，带分享 token）。条数规则和上一节相同。排序开关用服务机保存的配置。

## 帧邻域重排

默认开。文搜，以及图搜的「帧」和「每片最佳」会用。深入搜索不用这路，它走下面的像素重排。

命中之后，用同一个查询向量在附近帧里挑相似度更高的一帧。配置里有 `frame_neighbor_rerank_window_sec`（默认 4 秒）时，邻域按秒。没有这个键时，才用「前后各 N 帧」（默认 2）除以抽帧 fps。

设置里的重排条数默认 10。真正展开邻域的种子数是 `max(这个条数, 窗口 × 2, 12)`，并且不超过 32，也不超过这次取回的候选数。

## 深入搜索的像素重排

只重排列表最前面的几条，后面的保持召回顺序。

- 结果来自多条视频：只重排前 **3** 条。
- 结果都在同一条视频里：重排条数是设置值（默认 20），但不超过 **15**。
- 新时间和原来的种子最多差 **5** 秒。
- 探测默认跟索引步长（`image_pixel_rerank_probe_mode=index`）。改成 `fixed` 时，用设置里的时间窗（默认 2 秒）和步长（默认 0.5 秒）。
- 像素相似度低于 **0.58** 的探测点不采用。
- 查询图被判定为裁切过的画面时，不做像素重排，直接留 CLIP 顺序。

从一条已有命中再定位（截图定位）是另一条路：裁切过的图只信锚点附近 ±5 秒，结果 1 条；否则只对前 3 条做像素重排，时间同样最多挪 5 秒。召回阶段最多 20 条视频、每条 5 个种子、每条视频再取 100 帧。

## 文搜增强

默认关。只对纯文字、而且没有预先算好的查询向量。图搜、已经带了 `query_vector` 的请求、字幕、标签都不走。Agent 可以用 `text_enhance` 覆盖这台机器的开关。组合搜在打开增强、并且写了文字时，文字部分也可以走这路。

最多 **4** 路：原句一定在，另外最多 3 个短语。额外短语和原句的余弦至少 **0.18**，和已经选中的路至少要低于 **0.92**，避免重复。原句的票是额外路的 2 倍。同一条视频里相距 2 秒以内算同一个镜头，只投一票。界面上的分数仍是相似度，按融合名次从最高那条往下缩，不是 RRF 的原始分。最后仍截到这次窗口。

## 组合的文字和图片权重

同时有文字和参考图时，查询向量是两边加权再归一。默认各 **0.5**。权重会先加总再归一，所以 70/30 和 7/3 是同一个比例。只有文字时就是文搜；只有参考图时就是图搜。

## 结果聚组

默认开。字幕和标签不聚组。

同一条视频里，两帧相距不超过 **8** 秒、向量余弦至少 **0.82**，收成一组。没有向量时，只看时间，间隔收到 **4** 秒。不同视频要更像才并：标准 **0.94**，宽松 **0.90**，严格 **0.97**。

翻倍追加的下一批不并进上一批的组，所以列表只往后加，不整表重排。聚组后屏幕上的行数可以少于取回的命中。窗口用屏幕上的行数判断该不该翻倍：组收得很短时，滚到最后一行就会要下一批。

## 其它会改结果的开关

- **最低分**：按类型存在配置里（`image` / `text` / `compose` / `dialogue` / `image_chunk`）。0 表示不过滤。找图用组合搜那条。
- **素材范围**：全部，或选中的库 / 视频。选中后先多取，再丢掉范围外的。
- **跳过时段**：同一组绝对时间套到每条视频上。剩余不足 30 秒的视频整段保留。
- **文搜增强**、**邻域重排**、**像素重排**、**聚组**：规则在上面几节。最低分是绝对相似度，`0` 不过滤。
